## Designs

What every design does wrong (bugs) or differently (correct alternatives), from the header comments of the design files.

### acs_unit: Viterbi add-compare-select unit with validity

Origin: the add-compare-select block of a Viterbi decoder project.

* `golden` (correct): the reference design
* `bug_ignores_validity` (bug, missing qualification): compares the costs whatever the validity bits say, so an unreachable predecessor can win; the weak test keeps both predecessors valid
* `bug_ties_to_path1` (bug, tie-breaking rule): c0 >= c1 selects predecessor 1; the weak test has no ties
* `correct_priority` (correct): an if / else priority chain instead of a case

### adder_cla: Carry-lookahead adder with a logic-depth requirement

Origin: a carry-lookahead adder exercise.

* `golden` (correct): the reference design
* `bug_missing_cin_term` (bug, missing product term): the lookahead drops the all-propagate cin term for the top carry, so a carry from cin never reaches sum[N]; wrong only when every bit propagates and cin = 1, which 20 random vectors almost never hit
* `bug_plain_operator` (bug, fails the speed requirement): `a + b + cin`; correct, and Yosys maps + to its own lookahead adder, but with 16 levels: over the limit
* `bug_ripple` (bug, fails the speed requirement): correct sums, but C[i+1] = G[i] | P[i] & C[i] chains every carry through the previous one; only the logic-depth check sees it (a mistake seen in a graded submission)
* `correct_kogge_stone` (correct): a Kogge-Stone parallel-prefix adder: log2(N) levels of (generate, propagate) combination

### alu_reg: N-bit ALU with registered output and asynchronous reset

Origin: an ALU generalized from 1 to N bits.

* `golden` (correct): the reference design
* `bug_fixed_width` (bug, not parameterized): the arithmetic is done in 4 bits whatever N is; right at the default N = 4 only
* `bug_or_is_xor` (bug, wrong operator): op 11 computes a ^ b; the weak test only ORs 1 with 0, where XOR gives the same
* `bug_sub_swapped` (bug, swapped operands): computes b - a; the weak test subtracts equal operands
* `bug_sync_reset` (bug, synchronous instead of asynchronous reset): y clears only at the next clock edge; the weak test holds reset across an edge, so it cannot tell
* `correct_add_complement` (correct): subtraction as a + ~b + 1 on one adder

### bitrev_pipe: Dual-edge pipeline: capture on the falling edge, reverse/invert on the rising edge

Origin: a dual-edge register exercise.

* `golden` (correct): the reference design
* `bug_invert_only_if_reversed` (bug, control logic): applies the inversion only together with the reversal; caught even by the weak test
* `bug_rising_capture` (bug, wrong clock edge): captures din on the rising edge, so dout shows the word present half a cycle too early; the weak test holds din constant, which hides the timing
* `correct_bit_loop` (correct): one loop over the output bits in the rising-edge block

### clkdiv3: Glitch-free divide-by-3 clock with 50 % duty cycle

Origin: an odd clock-divider exercise.

* `golden` (correct): the reference design
* `bug_decoded_counters` (bug, glitch-prone clock (passes every zero-delay test)): two mod-3 counters, one per clock edge, and clk_out decoded from both with comparisons. The waveform is right in zero-delay simulation and in formal, but several counter bits change at the same edge, so the decode can glitch in hardware; only the timed gate-level grader sees it (a mistake seen in a graded submission)
* `bug_duty_33` (bug, wrong duty cycle): high for one clock period out of three; the period is right, so the weak edge count passes
* `correct_shift_ring` (correct): a 3-bit one-hot ring instead of a counter; q_pos is a ring bit, so clk_out is still an OR of two flip-flops

### conv_encoder_cfg: Programmable rate-1/2 convolutional encoder

Origin: a programmable convolutional encoder exercise.

* `golden` (correct): the reference design
* `bug_load_exclusive` (bug, control bits not independent): an if / else-if chain on load, so load = 11 loads only generator 0; the weak test loads one at a time (a mistake seen in a graded submission)
* `bug_reset_clears_generators` (bug, reset scope too wide): rst_n also clears the generators, so a reset in mid-stream loses the code; the weak test programs them after the only reset
* `bug_shift_while_loading` (bug, missing hold condition): the history shifts on every edge, also while a generator is loaded; the weak test releases reset only after loading, so the extra shifts never touch real data
* `correct_and_xor_loop` (correct): the convolution written as an explicit AND/XOR loop

### gray2bin: Registered Gray-to-binary converter

Origin: a Gray-code conversion exercise with registered input and output.

* `golden` (correct): the reference design
* `bug_comb_order` (bug, simulator-dependent always_comb): the loop runs from bit 0 up and reads bc[i+1] before this pass has computed it. By IEEE 1800, always_comb is not re-triggered by its own writes, so it uses stale values (Icarus); Verilator settles the block like a combinational network and gets the right answer. The same source earns different rewards in two simulators.
* `bug_latency_one` (bug, timing (pipeline depth)): the input register is missing, so b follows one edge early; the weak test waits three clocks per value
* `bug_pairwise_xor` (bug, wrong formula): b[i] = g[i+1] ^ g[i] (one XOR, not the prefix XOR); right for the weak test's values 0000, 0001, 0011
* `correct_shift_xor` (correct): prefix XOR as a sum of shifted copies

### log_shifter: Barrel shifter from 2:1 multiplexers only

Origin: a shift/rotate unit that must be built from a given 2:1 mux.

* `golden` (correct): the reference design
* `bug_behavioral` (bug, structural rule violated): correct function written with shift operators and ?: instead of mux2 instances; every functional grader passes it, only the structural check sees the violation (a mistake seen in a graded submission, in part)
* `bug_rotate_fill` (bug, off-by-one index): in the shift-by-2^s stages with s >= 1 the rotate fill takes the wrong wrapped bit; amounts of 0 and 1 are right, which is all the weak test uses for rotation
* `bug_two_stages` (bug, not parameterized): always two stages (amounts 0-3) whatever N is; right for N = 4 only
* `correct_two_networks` (correct): separate left and right log shifters, every selection still a mux2 instance

### maxlen_lfsr: Maximal-length LFSR with load and a period-complete pulse

Origin: a parameterized LFSR exercise, N = 2..8.

* `golden` (correct): the reference design
* `bug_done_on_load` (bug, output not qualified): done = (q == seed): high while loading, right after the load, and following the live seed input; the weak test only asks that done appears with q equal to the seed (a mistake seen in a graded submission)
* `bug_reset_ones` (bug, wrong reset value and type): asynchronous reset to all ones (a mistake seen in a graded submission); the weak test loads before looking
* `bug_taps_n8` (bug, wrong constant for one parameter value): N = 8 uses x^8 + x^4 + 1, which is not primitive (period < 255); every N the weak test uses is right
* `correct_counter_done` (correct): done from a shift counter instead of a comparison with the captured seed

### onehot_decoder: N-to-2^N decoder with enable

Origin: the decoder of a gate-level / dataflow / behavioral modeling exercise.

* `golden` (correct): the reference design
* `bug_bit_order` (bug, wrong bit order): selects bit 2^N-1-sel for every sel but 0; the weak test checks bit 0 for sel = 0 and only one-hotness after
* `bug_ignores_enable` (bug, missing control input): decodes sel whatever en is; the weak test never drives en low
* `bug_latch` (bug, inferred latch): no assignment when en = 0, so y keeps its old value instead of going to zero
* `correct_shift` (correct): a shift instead of an indexed write

### secded84: (8,4) extended Hamming decoder: correct one error, detect two

Origin: Hamming-code decoding exercises.

* `golden` (correct): the reference design
* `bug_no_overall_parity` (bug, missing detection): ignores P0, so it decodes like the 7-bit SEC code: any nonzero syndrome is "corrected", and two errors are miscorrected silently; the weak test has no double errors, but lint reports the unused input bit
* `bug_syndrome_map` (bug, wrong table entry): the syndromes of D2 and D1 are exchanged, so an error in D2 flips D1 and vice versa; the weak test only flips D4
* `correct_nearest_codeword` (correct): brute force: the code word at distance <= 1 among all 16, else a double error lint rejects it for a style warning (a 1-bit value added to an int), a false fail on correct code

### serial_rx: UART receiver with mid-bit sampling and framing errors

Origin: a UART receiver (Moore FSM) exercise.

* `golden` (correct): the reference design
* `bug_bit7_as_stop` (bug, missing protocol step): never samples the stop bit: after bit 7 it checks rx at the end of bit 7's own period, so every byte with bit 7 = 0 is dropped; all four bytes of the weak test have bit 7 = 1 (a mistake seen in a graded submission)
* `bug_data_cleared` (bug, output not held): data is cleared in the cycle after valid; a consumer that reads it later gets 0. The weak test reads data exactly when valid is high
* `bug_no_synchronizer` (bug, clock-domain crossing (invisible to simulation)): uses rx directly in the state machine with no synchronizer: metastability in hardware. No simulation or formal grader can see it; only the structural synchronizer rule of the synth grader does
* `bug_sample_at_edge` (bug, no timing margin): samples each bit right after its start (no half-bit offset); at the exact nominal rate it works, so the weak test passes, but a transmitter a few percent fast or slow is misread
* `correct_counter_sampling` (correct): one bit counter for the whole frame and a single sample-point comparison
* `correct_down_timer` (correct): synchronizer in its own process, a down-counting bit timer and a remaining-bits counter

### subtractor: Signed subtractor (A - B or B - A) with overflow flags

Origin: a configurable subtractor exercise.

* `golden` (correct): the reference design
* `bug_direction_inverted` (bug, control polarity): computes B - A when sub_ab = 1 and A - B when 0
* `bug_flags_swapped` (bug, swapped outputs): ovf_pos and ovf_neg exchanged; the weak test has no overflow at all
* `bug_unsigned_borrow` (bug, unsigned overflow rule for signed numbers): reports overflow from the borrow out of the top bit, which is the unsigned rule; caught even by the weak test (3 - 5 borrows but does not overflow)
* `correct_wide` (correct): computes the difference one bit wider and compares with the range

### twisted_ring_counter: N-bit Johnson counter with asynchronous clear and synchronous load

Origin: a twisted-ring counter exercise.

* `golden` (correct): the reference design
* `bug_clear_sync` (bug, asynchronous control made synchronous): clear waits for a clock edge; the weak test holds clear across an edge
* `bug_load_async` (bug, synchronous control made asynchronous): load acts as soon as load_n falls instead of at the clock edge; the weak test never loads
* `bug_shift_left` (bug, wrong direction): shifts left (0000 -> 0001 -> 0011 ...), a Johnson counter but not the one specified; same period, so the weak test's period check passes (a mistake seen in a graded submission)
* `correct_shift_operator` (correct): the twist written with a shift operator
